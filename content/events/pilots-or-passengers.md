# EES Lille: pilots or passengers?

An informal chat at the European Evaluation Society conference in Lille, on Thursday 29 October 2026, from about 16:30 at the café tables near Room 0.2.

It is for evaluators, technical or not, who want AI to follow an explicit evaluation method, in steps that somebody else could check or rerun, so that evaluators stay the pilots.

## Join in

This is not a new organisation. We have in mind a burst of about six months, after which we will see whether it is worth carrying on.

- **If you are interested, write to Steve Powell at [steve@pogol.net](mailto:steve@pogol.net?subject=Pilots%20or%20passengers)** and you will get the occasional invitation to calls and show-and-tell sessions. You do not need Slack or any particular software.
- **The hands-on work happens in the MERL Tech Slack.** Its channels come with membership of the [MERL Tech Community of Practice](https://merltech.org/cop/), which is free.

## Reading and tools

- [Pilots, not passengers](https://garden.causalmap.app/rubicon/): the argument. A frontier model can now answer the desk-based part of most evaluation questions in minutes, so how do evaluators keep choosing the method, and how can anybody else check what was done?
- [An open-source plugin for Claude](https://rubicon.causalmap.app) that we have been building. You agree the analysis with it before anything is read, then fixed rules count every number and check every quotation.
- [An open format for recording an analysis](https://app.causalmap.app/rubicon/spec/latest) so that somebody else can rerun it (latest version).

## From the MERL Tech Initiative

- [MERL Tech on GitHub](https://github.com/MERL-Tech): code from the MERL Tech Initiative (MTI).
- [MTI's playground](https://playground.merltech.org/): their experiments, including anything built by vibe coding (describing software to an AI and letting it write the code), as tools for responsible practice in monitoring, evaluation, research and learning.
